## Algorithm sketches

All algorithms receive a parent bounds, a list of child layout
nodes, and the current `EvalContext`. They compute per-child
bounds, recurse into each child with the new bounds + updated
context, and return the combined `NodeBounds[]`.

### lin

```
let flow = param("linDir", default = "fromL").flow()
let spacing = constraint(ConstrSp, default = 0)
let inner = pad_by_margins(parent_bounds, constraints)
let n = effective_children.length
if n == 0 return []
let unit = (inner.major_axis - spacing * (n - 1)) / n
for i, child in effective_children:
  let bounds_i = slice_along_axis(inner, axis = flow,
                                  offset = i * (unit + spacing),
                                  size = unit)
  apply_child(child, bounds_i)
```

### snake

```
let n = effective_children.length
let cols = parse_param("bkpt", default = ceil(sqrt(n)))
let rows = ceil(n / cols)
let spacing = constraint(ConstrSp, default = 0)
let cell_w = (inner.width - spacing * (cols - 1)) / cols
let cell_h = (inner.height - spacing * (rows - 1)) / rows
for i, child in effective_children:
  let row = i / cols
  let col = i % cols
  let bounds = BoundsRect {
    x = inner.x + col * (cell_w + spacing),
    y = inner.y + row * (cell_h + spacing),
    width = cell_w,
    height = cell_h,
  }
  apply_child(child, bounds)
```

### cycle

```
let n = effective_children.length
let radius = min(inner.width, inner.height) / 2 - cell_radius
let cx = inner.x + inner.width / 2
let cy = inner.y + inner.height / 2
let cell = min(inner.width, inner.height) / 3
for i, child in effective_children:
  let theta = -90 + i * (360 / n)        // -90 = top
  let x = cx + radius * cos(theta) - cell / 2
  let y = cy + radius * sin(theta) - cell / 2
  apply_child(child, BoundsRect { x, y, width = cell, height = cell })
```

### hier (hierRoot + hierChild)

The engine walks the data-model tree rooted at the current
context point and treats the layout node as describing one
sub-tree node. The root node takes the top 30 % of the bounds
and the immediate children share the bottom 70 %, each becoming
their own sub-tree with the same algorithm.

```
let root_h = inner.height * 0.30
let root_bounds = BoundsRect { x, y, width, height = root_h }
apply_root(root, root_bounds)
let children_y = y + root_h
let children_h = inner.height - root_h
let children_w = inner.width / children.length
for i, child_point in children:
  let bounds = BoundsRect {
    x = inner.x + i * children_w,
    y = children_y,
    width = children_w,
    height = children_h,
  }
  recurse(child_point, bounds)
```

### pyra

```
let n = effective_children.length
let acct = constraint(ConstrPyraAcctRatio, default = 0.25)
let row_h = inner.height / n
for i, child in effective_children: // i = 0 → top
  let frac = acct + (1.0 - acct) * (i / max(1, n - 1))
  let row_w = inner.width * frac
  let bounds = BoundsRect {
    x = inner.x + (inner.width - row_w) / 2,
    y = inner.y + i * row_h,
    width = row_w,
    height = row_h,
  }
  apply_child(child, bounds)
```

The pyramid is built with index `0` at the **top** (narrowest)
and `n-1` at the **base** (widest), matching the example in
§21.4.2 where the `pyra` algorithm is described as growing from
top-to-bottom along a vertical path.

## Conditional dispatch

```
fn evaluate_choose(branches, ctx):
  for b in branches:
    if b.is_else: continue
    if eval_predicate(b, ctx): return b.body
  for b in branches:
    if b.is_else: return b.body
  []

fn eval_predicate(b, ctx):
  let lhs = match b.func {
    FnCnt => axis_select(b.axis, b.pt_type, ctx).length
    FnDepth => ctx.depth
    FnMaxDepth => max_depth_of(ctx.data_model, ctx.context_id)
    FnPos => position_of(ctx.context_id, ctx.data_model)
    FnPosEven => position_of(...) % 2 == 0 ? 1 : 0
    FnPosOdd  => position_of(...) % 2 == 1 ? 1 : 0
    FnRevPos => reverse_position_of(...)
    FnVar => return false
  }
  let rhs = parse_int_or_zero(b.val.unwrap())
  match b.op { Some(OpEqu) => lhs == rhs, ... }
```

## Cross-package contracts

- Inputs come from `@drawing_ml/diagram` element wrappers
  (`CT_DiagramDefinition`, `CT_DataModel`); the existing stubs
  remain unchanged.
- The engine emits `NodeBounds` whose `shape` field is a
  `@preset_geometry.PresetShape`. Callers (renderers) feed it
  back into `@preset_geometry.build_geometry(shape, w, h)` to
  obtain a `ShapeGeometry`.
- Errors raise `@opc_errors.SchemaViolation` with the canonical
  §21.4 citation.
